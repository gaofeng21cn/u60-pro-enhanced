# U60 Pro Enhanced 交付

仓库 `docs/` 是安装事实的唯一来源。开始前完整读取 [docs/INSTALL.md](../../docs/INSTALL.md)，按 [docs/VALIDATION.md](../../docs/VALIDATION.md) 决定这次能宣称什么；本技能只补充容易做错的操作边界，不复制安装步骤。

## 硬边界

- 只支持国行 B28（`BD_FLYMODEMMU5250V1.0.0B28`，内核 `5.15.185-perf`）与国行 B31（`BD_CNMU5250V1.0.0B31`，内核 `5.15.194-perf`）。准备器按固件和设备身份双重绑定：一台设备准备的目录不能用到另一台，也不要在写入前跳过校验。
- 绝不执行 `reboot`、`poweroff`、`sysupgrade`、`firstboot` 或任何 eMMC/分区写入。回退只走 USB ADB 的 `restore-boot`；屏幕异常时先双击电源切回原厂界面。忽略这些边界会让设备只能靠现场操作恢复。
- 阶段语义固定：`prepare.py` 只读设备并联网下载依赖；`check` 上传材料并只读校验；只有 `install` 写入程序和启动项；`start` 才启动服务。**`check` 通过不构成安装授权。**
- 每台设备单独授权。对一台设备的安装或变更同意不适用于另一台，也不自动包含清数据、恢复出厂或重新分区这类动作。
- `u60-prepared-private/`、设备备份、订阅地址、节点配置、Clash 控制密钥、Tailscale state、IMEI/IMSI/ICCID、设备日志和截图只留在本机：不进入 Git，不贴到公开 issue。Mihomo 控制端口（`127.0.0.1:19090`）只在本机监听，不要新增映射或代理规则把它暴露出去。

## 构建

`sh scripts/build.sh` 必须使用 Zig 0.14.1；0.16 会失败，用 `ZIG=/path/to/zig` 显式指定。`sh scripts/test.sh` 只证明主机回归，不代替实机验收。构建与打包之后继续按 `docs/INSTALL.md` 的顺序准备、检查、安装、启动。

## 验收分层

安装包、已安装字节、生效配置、运行状态和业务可用是不同层次，不能互相替代。至少分别取得以下证据，再报告安装结果：

- 屏幕显示新界面，双击电源能在原厂与新界面之间双向切换；
- 原厂管理页和「增强功能」页可以按原有方式登录访问；
- 原有 Wi-Fi 热点和蜂窝上网仍然可用；
- 之后才单独验证 Clash / Tailscale，并区分「核心在运行」与「流量已被接管」。

B31 首装保持直连，USB 网口、Wi-Fi 中继和待机等网络协调服务默认停用。不要把 B28 的实机结果套到 B31，也不要在没有实测证据时宣称 UDP 或 IPv6 已被代理。

## 上游

本仓库 `main` 是维护主线。上游发布包只支持 B28：B31 设备不要指向上游安装包，通用修复可在本仓库验证后再整理成上游 issue / PR。
