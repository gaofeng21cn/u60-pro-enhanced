# 产品目标与当前基线

目标是把原厂 U60 Pro 增强为可靠、易用、可恢复的便携联网设备。小屏承担状态查看和常用操作，网页承担输入与高级管理；两端共享设置和结果。保留原厂固件、热点、管理页和 ADB，不通过刷机或牺牲恢复能力换取扩展功能。

## 已形成的功能基线

当前版本已落地并在一台 B31 上形成可使用的功能面：原厂保留、小屏与网页共用控制层、蜂窝/热点、2.4G Wi-Fi 接力、代理、组网、资源采样、安装升级回退、独立 SSH 维护、原生 Mac ECM＋ADB、正式开关和实体 USB 拔插恢复。细节与证据以 [验证范围](VALIDATION.md) 为准。

下列项目属于验收范围边界，不是假定已经完成：普通 UDP/IPv6 全量代理、5GHz 手机下游全链路、未实测的 USB 网卡型号、冷启动、长期功耗、第二台设备首装、Windows 安装和跨设备兼容。

## 第二阶段：Mac USB 联网（已落地，继续补充验收）

交付目标是 Mac 接上数据线即可获得原生网络，无需安装 Mac 驱动或反复打开终端；拔插和启动后可自动恢复，同时保留可用的 ADB 和独立维护通道。

当前原生 ECM＋ADB 已通过业务、启停、ADB 共存和实体拔插恢复验证，作为 B31 的免安装 Mac 联网能力交付；NCM 无需作为同一用户目标的前置条件，用户态 RNDIS 仅保留备用。技术路线与原厂约束由 [Mac USB 说明](MACOS-RNDIS.md) 唯一维护。

1. 核对原厂实际 USB owner、选中的 configuration、ADB function 所在配置及准确恢复方法；仅有 boot 配置文件或 product ID 不够。
2. 先证明独立 SSH、持久故障证据和有界恢复路径，不停止原厂 USB owner、不写分区、不直接解除旧试验封锁。
3. 一次受控试验分别核对 Mac 原生网卡、DHCP、管理页、绑定 USB 网口的 Google/Cloudflare HTTPS、主机侧 ADB 命令和失败恢复。
4. 正式入口和自动启动候选必须通过拔插、重复连接与冷启动后，才发布为可用能力。任一恢复步骤失败，立即停止试切并保留故障证据。
5. 若原生路线被具体设备限制证伪，记录限制与停止条件，再完成可选的 Mac 软件方案；不能将“工具已安装”算成联网完成。
