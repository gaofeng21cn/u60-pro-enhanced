# 一键网络自检

小屏与增强网页使用同一个只读动作 `diag.network`，返回可滚动的分层报告。不修改网络配置、DNS、路由、Clash、USB 或 ADB；检测会产生少量网络请求，按当前上网出口计入流量。

## 结果如何解读

| 检测层 | 检查内容 | 通过不代表什么 |
| --- | --- | --- |
| 出口路由 | 内核查询到 `1.1.1.1` 的 IPv4 路由、接口、源地址与网关 | 不发送探测包；不能证明所有目的地采用相同路由 |
| 出口接口与地址 | 该接口是否启用、内核是否报告链路就绪，是否具有与源路由一致的有效 IPv4 地址 | 不代表热点客户端已经联网，也不代表公网可达 |
| 系统 DNS | 系统解析器分别为 Google、Cloudflare 返回 IPv4 地址 | 可能使用本地缓存或当前 DNS 代理；不证明使用某个指定上游 DNS |
| 默认出口 HTTPS | 不指定应用代理，分别以 HTTPS HEAD 请求 Google 的 204 端点和 Cloudflare 首页 | 现有透明代理或策略路由仍可能生效，不能称为“直连测试” |
| Clash HTTP HTTPS | 只向 Clash 实时配置中、经本机地址检查的 HTTP 监听发送相同请求 | 远端地址族和分流由 Clash 决定，可能命中 DIRECT；不证明所有协议或客户端都被代理 |

每个 HTTPS 请求必须同时满足：curl 正常退出、完整数值测量、TLS 证书校验成功，以及端点返回预期状态（Google 204、Cloudflare 200）。重定向不自动跟随，连接失败、超时、DNS 失败、证书错误和 HTTP 状态异常分别显示。不会用 HTTP 可达替代 HTTPS 成功，也不会跳过证书验证。

只有全部检测项通过才显示“所有检测项通过”。Clash 未启动、HTTP 监听地址不属于本机或端口不合法时，代理检测显示“未检测”，默认出口检测仍会完成。检测部分通过时，报告明确指出默认出口或 Clash 哪条路径失败，并给出下一步建议。IPv6、UDP、下游热点设备和真实代理节点命中不在本自检的验收范围内。

## 时限与数据

路由查询最多 1 秒；两个系统 DNS 查询各最多 2 秒；每个 HTTPS 请求连接最多 4 秒、总请求最多 8 秒，另有独立的 8.5 秒进程上限；不重试、不跟随重定向。Clash 配置读取沿用控制器已有的超时限制。完整检测通常在数秒到约 45 秒内返回，不在后台循环。

curl 禁用用户配置文件、使用干净环境、仅允许固定 HTTPS 端点，以 HEAD 请求只取响应头，不下载响应体。报告不包含响应体、Cookie、订阅、代理密钥、Wi-Fi 密码或节点凭据。证书校验或证书文件错误提示检查设备时间和 CA；curl 35 的 TLS 握手失败提示检查当前节点、远端连接与分流，不能仅据此断定是时间或 CA 问题。不通过关闭证书校验制造成功结果。

控制器返回既有 `report.title`、`report.lines`，供小屏和网页直接显示；额外的 `report.checks` 为每项记录 `passed`、`failed` 或 `skipped`、原因和建议。HTTPS 项记录实际 curl 退出码、HTTP 状态、TLS 校验结果和耗时。`report.summary` 分别记录默认出口和显式 Clash 路径的结果；顶层 `ok: true` 只表示诊断报告已生成，不表示网络检测通过。

旧 `diag.web` 动作保持兼容，仍是 Google／百度的显式 Clash 网站测试；新的一键自检用于定位完整链路的失败层。

## 开发验证

```sh
cc -O1 -I panel -I panel/vendor tests/test-network-diagnostics.c panel/vendor/cJSON.c -lm -o /tmp/test-network-diagnostics
/tmp/test-network-diagnostics
```

测试运行真实 C 报告代码和真实进程执行／退出／超时路径，以测试程序替代 curl，不连接外部网络。它覆盖 DNS、TLS、HTTP 重定向、部分可用、代理不可用、本机监听校验、进程错误与输出异常。主机测试不能代替设备上的实际出口、证书环境与热点客户端验收。
