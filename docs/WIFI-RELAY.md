# Wi-Fi 接力

这是原厂驱动上的单上游 Wi-Fi 扩展，不是 Mesh 或通用 OpenWrt 中继。B28 既有硬件证据与 B31 当前验证范围分别见[验证记录](VALIDATION.md)。

## 使用

1. 开启 5G 主热点、关闭访客热点，将 USB 网口设为 LAN。2.4G 主热点可以保留开启，也可在中继期间单独开关。
2. 屏幕进入“网络 → Wi-Fi → 连接 / 更换上游 Wi-Fi”；原厂网页进入“增强功能 → 网络”的同名入口。
3. 扫描直接执行，失败原因持续显示；选择加密网络后直接进入密码键盘。字母、数字、符号可直接切换，触控键至少 44 像素，支持显示/隐藏密码。连接失败时只在内存保留输入，返回取消或连接成功后清除；也可在已登录的管理网页输入。扫描结果按 2.4G、5G 分开，同名同频段、相同加密方式的重复接入点保留较强信号。选择网络，在自己的设备界面输入密码；不必先手动断开现有中继。
4. 停止时点总览的“中继管理 / 停止”，或进入“网络 → Wi-Fi”点顶部“停止 Wi-Fi 中继”。确认后恢复蜂窝等原出口，保持自身热点及保存的上游密码；再次点“启动 Wi-Fi 中继”即可重连。
5. 连接后显示实际“2.4G 上游中继”或“5G 上游中继”。仅连接一个上游，不叠加两条 Wi-Fi 带宽。

凭据保存在 U60 本机权限受限的配置文件中。自动重连保持所选频段，可在该频段内选择兼容的同名接入点；不会默认跨到另一频段。开启“开机连接已保存网络”后，关机前仍处于开启状态的接力会在启动入口尝试恢复；关闭该选项不影响当前连接。启动入口回归不等于完整冷启动硬件验收。关闭接力后可以“忘记保存的上游”，删除本机保存的网络凭据。当前只保留一个上游，不提供多个已知网络及优先级。

同频热点要与上游协调信道。B28 使用停用热点 BSS、修改运行时参数、再启用的路径；B31 使用原生信道切换，避免其固件在重新启用时把带宽恢复成不匹配值。两者均核对热点与驱动实际信道，不能只根据命令返回成功判定。失败后尝试恢复原信道，恢复未确认则保留恢复记录；原厂持久 Wi-Fi 设置不重写。恢复原 160 MHz 几何时可能需要等待 DFS 检查，界面会保持操作中提示。

## 流量与冲突

热点和手动 LAN 下属设备共用当前上游；已有 Clash IPv4 TCP/DNS 分流及 Tailscale 子网配置继续工作。路由状态、真实下属请求和实际出口流量增量须一起验收，不能只看页面显示“已连接”。

- 默认允许断线回退蜂窝并消耗 SIM 流量。可选择“禁止蜂窝回退”：接力开启期间在 IPv4/IPv6 OUTPUT 和 FORWARD 阻断 `rmnet+` 出站，覆盖下游直连与本机代理；更换上游时保留保护。该选项也会阻断经蜂窝的远程管理，不关闭基带，不保证整机零流量；启动保护在接力 owner 恢复后生效，不宣称原厂开机阶段零泄漏。主动关闭接力会解除保护并恢复原出口。
- 中继期间互联网 IPv6 沿用阻断默认出口的策略；不宣称任意 IPv6/UDP 代理或全面防泄漏。
- 当前要求 USB LAN、访客热点关闭和 5G 主热点开启。与原厂休眠、热点关闭或 USB 冲突时释放自建 STA，条件恢复后尝试重连。
- 2.4G 支持信道 1–13；5G 支持非 DFS 的 36/40/44/48、149/153/157/161/165。DFS 不在列表中；160MHz、地区差异与拥塞组合未全面验证。
- 互联网探测每 30 秒最多检查一轮，curl 绑定 `u60sta` 并绕过代理环境，访问 Google/Cloudflare 的公开 HTTP 204 检测端点，不携带账户信息。204 表示探测通过；重定向、200 或 511 提示可能需要网页认证；两端均失败显示不可达。结果超过 90 秒视为未知。检测站点可能被限制，失败不能证明所有互联网均不可用；它不自动改变路由或执行门户登录。

## 本次证据与未验证范围

一台国行 B31 上：2.4G 上游关联、DHCP 地址、默认出口、双热点状态和绑定 STA 的 Google 204、Cloudflare/百度 HTTPS 200 已确认。Mihomo 内部 NTP 修复后，经本机代理访问 Google 204 与 Cloudflare 200 通过，原厂时钟未修改。Mac 绑定 U60 热点接口、不设置显式代理，Google 204、Cloudflare 200 且证书校验通过；Cloudflare 下载同时回读到 Mihomo `Redir` 连接及非 DIRECT 策略链。小屏停止/启动均实际点击通过，停止后恢复蜂窝、双热点保留，重启中继后无需重输密码且恢复 ONLINE。该结果限定 IPv4 TCP，未证明 DNS、普通 UDP 和 IPv6 全量覆盖。

一台国行 B28 上：修复后的 2.4G 上游下，用户分别连接自身两个热点，百度、Google 都正常。5G 上游有设备及 USB 下属自动业务测试，但修复后的完整手机双热点验收尚未完成。相关测试期间中继接口产生流量、蜂窝收发增量为零，只代表这些测试时段，不是永不消耗蜂窝的保证。

Tailscale 在线节点与下属到 Tailnet 的自动通信通过；此前外部手机到子设备的人工验收有记录，但新修复没有再次完成外部手机全链路验收。真实长休眠、冷启动、长期负载/功耗、全部上游加密组合、第二台新设备首装仍未验证。

本版还修复了首页标题周期性闪为运营商的问题：慢速后台快照不再覆盖本地实时出口。实际路由回退仍会显示，未通过隐藏蜂窝状态来消除闪动。

出现异常时先用 UI 关闭中继，确认两热点与原出口恢复。排查时优先 USB ADB，保留密码、订阅、Tailscale 身份和原厂设置；不要反复重启整机或删除配置。已有本项目安装使用[原地升级入口](INSTALL.md)，不能用首装脚本强制覆盖。
